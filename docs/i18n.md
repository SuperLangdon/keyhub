# 语言包（i18n）结构与维护

所有界面文案集中在 `assets/i18n/` 下，**每语言一个 JSON 文件**，键名即文案身份，改文案只动 JSON、不动代码。

## 文件与查找规则

| 文件 | 内容 |
| --- | --- |
| `zh.json` / `en.json` | 顶层 `tc_*` 平级键（原驱动语言包词条，键名与驱动资源一致，**勿改键名**）+ `app` 段（本应用界面文案，按模块分组） |
| `kr.json` | 仅 `tc_*` 驱动词条；界面文案未翻译，查找时自动回退英文 |

`js/i18n.js` 提供 `t(key, params)`：

- `tc_*` 不含点，按平级键直取（如 `t('tc_kb_led1')`）；
- `app.*` 按点路径取（如 `t('app.nav.lighting')` → `pack.app.nav.lighting`）；
- 查找链：当前语言 → 英文兜底（kr 未译场景）→ 键名本身（漏键直接可见，便于排查）；
- `params` 提供占位值：词条中的 `{x}` 被替换，如 `t('app.keys.writeOk', { n: 3 })`。**同一词条中英双方的占位符集合必须一致**。

## app 段分组

`common`（跨页共用词）/ `nav` / `topbar` / `gate`（免责声明门）/ `conn`（主页连接中心与添加向导）/ `keys` / `light` / `macro` / `screen` / `settings` / `dbg`（HID 控制台）/ `fn`（键位功能标签，vk.js）。

同文异义各自成键（如 `关闭` 有 `common.close` 与 `common.off` 两处）；同一文案多处复用共一个键（如 `写入键盘` = `app.keys.writeKeyboard`）。

## 三种文案来源的接入方式

1. **JS 渲染**（绝大多数）：直接 `t('app.xxx.yyy')`。模块级常量里的文案要用惰性函数（`() => [...]`），否则首次 import 时固化语言、切换后不更新。
2. **HTML 静态节点**：加 `data-i18n-text` / `data-i18n-html` / `data-i18n-title` / `data-i18n-aria` / `data-i18n-placeholder` 属性，值为键名；`main.js applyStaticI18n()` 在每次 `applyLang()` 后统一扫描写入（`<title>` 与 `<html lang>` 也在此同步）。HTML 内保留中文默认值供首屏兜底。
3. **驱动词条**（灯效名、多媒体键名等）：沿用 `tc_*` 平级键，三语齐全，不需要 fallback。

## 新增 / 修改文案

1. 在 `zh.json` 与 `en.json` 的对应分组里加键（两边同时加，占位符一致）；
2. 代码 / HTML 属性引用键名；
3. 漏键无需担心显示错乱——`t()` 会直接把键名渲染出来，一眼可辨。

## 有意保留中文的部分

HID 调试台的 `devLog` 日志行、适配诊断包内容、issue 模板（`connect.js adapterIssueText`）是开发者排障工件，保持中文不随界面语言切换；型号名与 sub 描述来自型号注册表数据，同样不翻译。
